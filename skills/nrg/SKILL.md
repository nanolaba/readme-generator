# Editing NRG-generated documentation

NRG builds one Markdown file per language from a `*.src.md` template: `README.src.md` produces
`README.md`, `README.ru.md`, and so on. The generated files are build output.

## Rules

1. Never edit a generated file. Its first line names the template; `nrg --is-generated FILE`
   prints it, and `nrg --locate FILE:LINE` names the exact template line (through imports).
2. Edit the `.src.md` template or the fragment it imports. A line tagged `<!--en-->` has a
   counterpart for every other language right next to it — change all of them.
3. After the change, run `nrg --validate -f TEMPLATE.src.md`, fix every `ERROR`, then
   `nrg -f TEMPLATE.src.md`. Use `./nrgw` instead of `nrg` when the repository has it.
4. Commit the template together with the regenerated files.

Exit codes: `0` ok, `1` (`--check`) a generated file is stale, `2` the template is invalid,
`64` the command line is wrong. Add `--format json` for machine-readable results: every
diagnostic has a stable `code` and a `hint` naming the fix.

## Syntax

The complete template syntax — languages, properties, escapes, markers and every widget's
parameters — is in [SYNTAX.md](SYNTAX.md). `nrg --help syntax` prints the same card for the
installed version.

## Useful commands

- `nrg --manifest` — every template, its outputs and the files it reads.
- `nrg --affected FILE` — the templates to regenerate after FILE changed.
- `nrg --agent-rules --write AGENTS.md` — keep the project's agent instructions in sync.
