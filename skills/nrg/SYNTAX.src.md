## ${en:'Rules', ru:'Правила'}

- A file whose first line says `This file was automatically generated by Nanolaba Readme Generator` is output. Never edit it: edit the template it names (`nrg --is-generated FILE`, `nrg --locate FILE:LINE`) and regenerate.<!--en-->
- `X.src.md` produces `X.md` for the default language and `X.<lang>.md` for the others (unless `nrg.fileNamePattern` says otherwise; `nrg --manifest` lists the real outputs).<!--en-->
- After every change: `nrg --validate -f X.src.md`, then `nrg -f X.src.md` (`./nrgw` instead of `nrg` when the repository has the wrapper). Commit the template together with the regenerated files.<!--en-->
- Exit codes: `0` ok, `1` `--check` found a stale file, `2` invalid template / failed generation, `64` wrong command line.<!--en-->
- Файл, первая строка которого говорит `This file was automatically generated by Nanolaba Readme Generator`, — результат генерации. Не правьте его: правьте названный в нём шаблон (`nrg --is-generated FILE`, `nrg --locate FILE:LINE`) и перегенерируйте.<!--ru-->
- `X.src.md` даёт `X.md` для языка по умолчанию и `X.<lang>.md` для остальных (если `nrg.fileNamePattern` не задаёт иного; настоящие выходные файлы покажет `nrg --manifest`).<!--ru-->
- После каждой правки: `nrg --validate -f X.src.md`, затем `nrg -f X.src.md` (`./nrgw` вместо `nrg`, если в репозитории есть обёртка). Коммитьте шаблон вместе с перегенерированными файлами.<!--ru-->
- Коды возврата: `0` — успех, `1` — `--check` нашёл устаревший файл, `2` — некорректный шаблон / сбой генерации, `64` — неверная командная строка.<!--ru-->

## ${en:'Languages', ru:'Языки'}

```markdown
<\!--@nrg.languages=en,ru-->
<\!--@nrg.defaultLanguage=en-->

This line goes to README.md only<\!--en-->
Эта строка попадёт только в README.ru.md<\!--ru-->
A line without a marker goes to every file.
Inline: \${en:'Hello', ru:'Привет'} or \${en:"It's", ru:"Это"}; double a quote to escape it: \${en:'It''s'}
```

- A language marker applies to the whole line, wherever it stands on the line.<!--en-->
- Keep translations together: every run of tagged lines needs lines for every declared language, and every `\${en:'…'}` construct an entry for every language the line is shown in (`--validate` reports both). Mark a line meant for one language only with `<\!--nrg.parity.ignore-->`.<!--en-->
- Языковой маркер действует на всю строку, в каком бы месте строки он ни стоял.<!--ru-->
- Держите переводы вместе: в каждой серии строк с маркерами нужны строки для каждого языка, а в каждой конструкции `\${en:'…'}` — запись для каждого языка, в котором выводится строка (`--validate` сообщает об обоих случаях). Строку только для одного языка помечайте `<\!--nrg.parity.ignore-->`.<!--ru-->

## ${en:'Properties and values', ru:'Свойства и значения'}

```markdown
<\!--@name=Value-->                 declare (the line itself is not output)
<\!--@name.ru=Значение-->           per-language override of name
\${name}                            use; an undefined name stays in the output as written
\${env.NAME:fallback}               environment variable
\${pom.version} \${pom.properties.x} \${npm.version} \${gradle.version}   build descriptors, with :fallback
```

- `nrg.*` properties configure NRG: `nrg.languages`, `nrg.defaultLanguage`, `nrg.fileNamePattern` (placeholders `<base>`, `<lang>`, `<LANG>`), `nrg.defaultLanguageFileNamePattern`, `nrg.fileNamePattern.<lang>`, `nrg.widgets`, `nrg.pom.path` / `nrg.npm.path` / `nrg.gradle.path`, `nrg.noHeader`, `nrg.headerText`, `nrg.allowRemoteImports`, `nrg.validate.parity`, `nrg.variants` (output variants; `\${nrg.variant}` is the current one, `<variant>` its file name placeholder, `nrg.variant.<name>.file` its file).<!--en-->
- Свойства `nrg.*` настраивают NRG: `nrg.languages`, `nrg.defaultLanguage`, `nrg.fileNamePattern` (плейсхолдеры `<base>`, `<lang>`, `<LANG>`), `nrg.defaultLanguageFileNamePattern`, `nrg.fileNamePattern.<lang>`, `nrg.widgets`, `nrg.pom.path` / `nrg.npm.path` / `nrg.gradle.path`, `nrg.noHeader`, `nrg.headerText`, `nrg.allowRemoteImports`, `nrg.validate.parity`, `nrg.variants` (варианты вывода; `\${nrg.variant}` — текущий вариант, `<variant>` — его плейсхолдер в имени файла, `nrg.variant.<name>.file` — его файл).<!--ru-->

## ${en:'Markers', ru:'Маркеры'}

```markdown
<\!--nrg.ignore-->                        drop this line from every output
<\!--nrg.ignore.begin--> … <\!--nrg.ignore.end-->
<\!--nrg.freeze id="x"--> … <\!--/nrg.freeze-->   keep what the output file already has here
<\!--toc.ignore-->                        keep this heading out of the table of contents
<\!--nrg.parity.ignore-->                 this line is meant for one language only
<\!--nrg.translation.ok-->                this one-sided edit needs no translation (--stale-translations)
<\!--variant:a,b--> / <\!--variant:!c-->   keep the line in variants a and b / everywhere but c
```

## ${en:'Common mistakes', ru:'Частые ошибки'}

1. Editing `README.md` instead of `README.src.md`.<!--en-->
2. Updating one language and forgetting the line tagged for the other one next to it.<!--en-->
3. Writing <code>&lt;!--&#92;@nrg.languages=…--&gt;</code> in an example: that escape is cosmetic and still declares the property; write <code>&lt;&#92;!--@nrg.languages=…--&gt;</code> to show it.<!--en-->
4. Writing `\${name}` literally in prose: escape it as `\\${name}`.<!--en-->
5. Guessing a widget parameter (`maxDepth` instead of `max-depth`): unknown parameters are errors in `--validate`.<!--en-->
6. Putting a block opener or closer on a line with other text.<!--en-->
7. Writing a version number by hand instead of `\${pom.version}` / `\${npm.version}`.<!--en-->
8. Pasting a code sample instead of `\${widget:import(path='…', region='…')}` from a real, compiled file.<!--en-->
9. Using `--check` as the CI gate for a template that renders `\${widget:date}`: it differs on every run; use `--validate`.<!--en-->
10. Forgetting that paths in a template are relative to that template's own file and must stay inside the project root.<!--en-->
1. Правка `README.md` вместо `README.src.md`.<!--ru-->
2. Обновление одного языка без соседней строки с маркером другого.<!--ru-->
3. <code>&lt;!--&#92;@nrg.languages=…--&gt;</code> в примере: такое экранирование косметическое и всё равно объявляет свойство; чтобы показать строку, пишите <code>&lt;&#92;!--@nrg.languages=…--&gt;</code>.<!--ru-->
4. `\${name}` в тексте как есть: экранируйте его как `\\${name}`.<!--ru-->
5. Угаданный параметр виджета (`maxDepth` вместо `max-depth`): неизвестные параметры — ошибки `--validate`.<!--ru-->
6. Открывающий или закрывающий тег блока на одной строке с другим текстом.<!--ru-->
7. Номер версии, написанный руками, вместо `\${pom.version}` / `\${npm.version}`.<!--ru-->
8. Вставленный вручную пример кода вместо `\${widget:import(path='…', region='…')}` из настоящего компилируемого файла.<!--ru-->
9. `--check` как проверка в CI для шаблона с `\${widget:date}`: он расходится при каждом запуске; используйте `--validate`.<!--ru-->
10. Забытое правило: пути в шаблоне задаются относительно его собственного файла и не должны выходить за корень проекта.<!--ru-->
