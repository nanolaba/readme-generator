### ${en:'Unreleased', ru:'В разработке'} (${devVersion})<!--toc.ignore-->

- **The header of a generated file names its template**: the default comment at the top of every output now reads `This file was automatically generated by Nanolaba Readme Generator (NRG) from README.src.md` and `Do not edit it by hand: change README.src.md and regenerate`, with the template path relative to the output file. Whoever opens the generated file first — a contributor or a coding agent — learns which file to edit. The NRG version is no longer part of the default header, so upgrading NRG no longer changes every generated file and no longer fails `--check`. `--header-text` / `nrg.headerText` / `<headerText>` accept the placeholders `<source>`, `<lang>` and `<version>`, and `--\>` in the header text produces `-->`, so a template can set a header that is itself an HTML comment. **Behaviour change:** the first two lines of every generated file change once — regenerate after upgrading. Closes [#68](https://github.com/nanolaba/readme-generator/issues/68).<!--en-->
- **Заголовок сгенерированного файла называет шаблон**: комментарий по умолчанию в начале каждого выходного файла теперь звучит как `This file was automatically generated by Nanolaba Readme Generator (NRG) from README.src.md` и `Do not edit it by hand: change README.src.md and regenerate`, путь к шаблону указан относительно выходного файла. Тот, кто открыл сгенерированный файл первым, — контрибьютор или ИИ-агент, — сразу узнаёт, какой файл править. Версии NRG в заголовке по умолчанию больше нет: обновление NRG больше не меняет все сгенерированные файлы и не валит `--check`. `--header-text` / `nrg.headerText` / `<headerText>` понимают плейсхолдеры `<source>`, `<lang>` и `<version>`, а `--\>` в тексте заголовка даёт `-->`, так что шаблон может задать заголовок, который сам является HTML-комментарием. **Изменение поведения:** первые две строки каждого сгенерированного файла один раз меняются — перегенерируйте файлы после обновления. Закрывает [#68](https://github.com/nanolaba/readme-generator/issues/68).<!--ru-->
- **`--validate` catches near-miss syntax**: new errors for a parameter a built-in widget does not have (`\${widget:toc(maxDepth='2')}`), for an unclosed `\${widget:if(...)}` / `\${widget:details(...)}` block or a stray closer, and for an undefined `\${name}` that is one or two edits away from a declared property (`\${stableVerison}`). New warnings — reported without failing the run — for other undefined `\${name}` references (they stay in the output as written), for `\${pom.…}` / `\${npm.…}` / `\${gradle.…}` references that render empty, and for <code>&lt;!--&#92;@nrg.languages=…--&gt;</code>-style examples, which declare the property for real. Unknown widget names, widget parameters and language markers get a "did you mean …?" hint. Widgets passed with `--widgets` are now known to `--validate`, and an import with `run-generator='false'` is no longer scanned as a template. Custom widgets opt into the parameter check by overriding the new `NRGWidget.getParameterNames()`. Closes [#69](https://github.com/nanolaba/readme-generator/issues/69).<!--en-->
- **`--validate` ловит синтаксис «почти правильно»**: новые ошибки — параметр, которого нет у встроенного виджета (`\${widget:toc(maxDepth='2')}`), незакрытый блок `\${widget:if(...)}` / `\${widget:details(...)}` или одинокий закрывающий тег, необъявленный `\${name}`, отличающийся на одну-две правки от объявленного свойства (`\${stableVerison}`). Новые предупреждения, не валящие запуск, — прочие необъявленные `\${name}` (остаются в выводе как есть), ссылки `\${pom.…}` / `\${npm.…}` / `\${gradle.…}`, которые рендерятся пустыми, и примеры вида <code>&lt;!--&#92;@nrg.languages=…--&gt;</code>, которые на самом деле объявляют свойство. К неизвестным именам виджетов, параметрам и языковым маркерам добавлена подсказка «did you mean …?». `--validate` теперь знает виджеты, переданные через `--widgets`, а импорт с `run-generator='false'` больше не проверяется как шаблон. Пользовательские виджеты включают проверку параметров, переопределив новый метод `NRGWidget.getParameterNames()`. Закрывает [#69](https://github.com/nanolaba/readme-generator/issues/69).<!--ru-->
- **`--validate` checks that translations stay together**: a run of language-tagged lines (blank lines do not end it) that has no line for one of the languages in `nrg.languages` is an error, and so is a `\${en:'…'}` construct that lacks an entry for a language the line is shown in (it renders empty there) or names an undeclared language (the whole construct is left in the output as written). Inside such a run, a different sequence of headings, list items, table rows, code blocks or paragraphs between languages is reported as a warning. A line meant for one language only is marked with the new `<\!--nrg.parity.ignore-->` marker (removed from the output); `nrg.validate.parity=false` turns the checks off. **Behaviour change:** templates with one-language content now fail `--validate` until it is translated or marked. Closes [#70](https://github.com/nanolaba/readme-generator/issues/70).<!--en-->
- **`--validate` проверяет, что переводы не расходятся**: серия строк с языковыми маркерами (пустые строки её не прерывают), в которой нет строк для одного из языков `nrg.languages`, — ошибка; ошибка и конструкция `\${en:'…'}` без записи для языка, в котором выводится строка (там она рендерится пустой), или с записью для необъявленного языка (тогда вся конструкция остаётся в выводе как есть). Если внутри такой серии у языков различается последовательность заголовков, пунктов списка, строк таблицы, блоков кода или абзацев, выводится предупреждение. Строку, предназначенную только для одного языка, помечают новым маркером `<\!--nrg.parity.ignore-->` (из вывода он удаляется); `nrg.validate.parity=false` отключает проверки. **Изменение поведения:** шаблоны с текстом только на одном языке теперь не проходят `--validate`, пока его не переведут или не пометят. Закрывает [#70](https://github.com/nanolaba/readme-generator/issues/70).<!--ru-->
- **`--format json` and `--format github`**: `--format json` prints one JSON document on stdout — the files a run wrote or checked with their status (`written` / `unchanged` / `ok` / `stale` / `missing` / `invalid`) and every diagnostic with a stable `code` and a separate `hint` — and moves all logging to stderr, so agents, hooks and CI steps no longer parse log lines. `--format github` prints the same findings as GitHub Actions `::error` / `::warning` annotations. Maven plugin: `<format>`. Closes [#71](https://github.com/nanolaba/readme-generator/issues/71).<!--en-->
- **Distinct exit codes**: `1` now means only that `--check` found a stale or missing file; `2` — a template is invalid (`--validate`) or generation failed; `64` — the command line is wrong (unknown or conflicting options, a missing source file, patterns that match nothing). A batch exits with the highest code. An exception thrown while rendering (for example an import outside the project root) no longer escapes `NRG.run` — it fails that file with code `2`. A failed text-mode `--check` ends with `Regenerate with: nrg -f …`. **Behaviour change** for scripts that test for exit code `1` specifically.<!--en-->
- **`--format json` и `--format github`**: `--format json` печатает в stdout один JSON-документ — файлы, которые запуск записал или проверил, с их статусом (`written` / `unchanged` / `ok` / `stale` / `missing` / `invalid`), и все диагностики со стабильным `code` и отдельной подсказкой `hint`, — а логирование переносит в stderr, так что агентам, хукам и шагам CI больше не нужно разбирать строки лога. `--format github` печатает те же находки как аннотации GitHub Actions `::error` / `::warning`. Maven-плагин: `<format>`. Закрывает [#71](https://github.com/nanolaba/readme-generator/issues/71).<!--ru-->
- **Раздельные коды возврата**: `1` теперь означает только, что `--check` нашёл устаревший или отсутствующий файл; `2` — шаблон некорректен (`--validate`) или генерация не удалась; `64` — неверная командная строка (неизвестные или конфликтующие опции, несуществующий исходный файл, паттерны без совпадений). Пакетный запуск завершается с наибольшим кодом. Исключение при рендеринге (например, импорт за пределами корня проекта) больше не вылетает из `NRG.run` — файл завершается с кодом `2`. Неудачный `--check` в текстовом режиме заканчивается строкой `Regenerate with: nrg -f …`. **Изменение поведения** для скриптов, которые проверяют именно код `1`.<!--ru-->
- **`nrgw` wrapper**: `nrg --init-wrapper [--wrapper-version X] [--wrapper-sha256 HEX]` writes `nrgw`, `nrgw.cmd` and `.nrg/wrapper.properties` (release version and the sha256 of its zip, taken from the checksum published with the release). Committed to a repository, `./nrgw` downloads that release once into `~/.nrg/wrapper/`, verifies it and runs it — the same command for a contributor, a CI job and a coding agent in a fresh sandbox, with only Java installed. Exit code `69` when the wrapper cannot provide NRG. Closes [#72](https://github.com/nanolaba/readme-generator/issues/72).<!--en-->
- **Обёртка `nrgw`**: `nrg --init-wrapper [--wrapper-version X] [--wrapper-sha256 HEX]` записывает `nrgw`, `nrgw.cmd` и `.nrg/wrapper.properties` (версия релиза и sha256 его архива, взятый из опубликованной с релизом контрольной суммы). Закоммиченная в репозиторий, `./nrgw` один раз скачивает этот релиз в `~/.nrg/wrapper/`, проверяет и запускает его — одна и та же команда для контрибьютора, задачи CI и ИИ-агента в свежей песочнице, где установлена только Java. Код `69`, если обёртка не может предоставить NRG. Закрывает [#72](https://github.com/nanolaba/readme-generator/issues/72).<!--ru-->
- **`--manifest`, `--is-generated`, `--affected`**: read-only queries that answer what a template writes and reads without generating anything. `--manifest` lists each template's output per language and its inputs — imported files (transitively), `fileTree` directories, the descriptors behind `\${pom.…}` / `\${npm.…}` / `\${gradle.…}` — plus `dynamic` sources (remote imports, `exec`, environment variables, the date); `--format json` for tools. `--is-generated <file>` exits `0` and names the template when the file is generated (a hook can block edits to it), `--affected <file>…` prints the templates to regenerate. Without sources, every `*.src.md` that no other template imports is used. Closes [#73](https://github.com/nanolaba/readme-generator/issues/73).<!--en-->
- **`--manifest`, `--is-generated`, `--affected`**: запросы только на чтение, которые без генерации отвечают, что шаблон пишет и что читает. `--manifest` перечисляет для каждого шаблона выходной файл каждого языка и входы — импортируемые файлы (транзитивно), каталоги `fileTree`, дескрипторы за `\${pom.…}` / `\${npm.…}` / `\${gradle.…}`, — а также `dynamic`-источники (удалённый импорт, `exec`, переменные окружения, дата); для инструментов — `--format json`. `--is-generated <file>` завершается с кодом `0` и называет шаблон, если файл сгенерирован (хук может запретить его правку), `--affected <file>…` печатает шаблоны, которые нужно перегенерировать. Без исходников используются все `*.src.md`, которые не импортирует другой шаблон. Закрывает [#73](https://github.com/nanolaba/readme-generator/issues/73).<!--ru-->
- **`--locate FILE:LINE[-LAST]`**: names the template line that produces a line of a generated file, with the chain of imports that led there — `README.ru.md:340: docs/Launching.src.md:45 <- imported at README.src.md:36` — through ignore blocks, `if` / `details` blocks, imports with `lines=` / `region=` / `wrap=` / `heading-offset=`, and frozen regions; widget output that cannot be traced further names the widget's line. `--format json` for agents. Library users get the same map from `GeneratorConfig.setCollectSourceMap(true)` and `GenerationResult.getSourceMap()`; without it nothing is collected and the output is unchanged. Closes [#74](https://github.com/nanolaba/readme-generator/issues/74).<!--en-->
- **`--locate FILE:LINE[-LAST]`**: называет строку шаблона, из которой получается строка сгенерированного файла, и цепочку импортов, которая к ней ведёт, — `README.ru.md:340: docs/Launching.src.md:45 <- imported at README.src.md:36`, — сквозь ignore-блоки, блоки `if` / `details`, импорты с `lines=` / `region=` / `wrap=` / `heading-offset=` и замороженные области; вывод виджета, который дальше не проследить, указывает на строку виджета. Для агентов — `--format json`. Пользователи библиотеки получают ту же карту через `GeneratorConfig.setCollectSourceMap(true)` и `GenerationResult.getSourceMap()`; без этого ничего не собирается и вывод не меняется. Закрывает [#74](https://github.com/nanolaba/readme-generator/issues/74).<!--ru-->
- **`--agent-rules`**: prints the instruction block for `AGENTS.md` / `CLAUDE.md` computed from the templates — the generated files and their templates, the fragments to edit, the source files embedded in the docs, the languages and the exact validate / generate commands (`./nrgw` when the wrapper is present). `--write AGENTS.md` inserts or replaces the block between `<\!-- nrg:agent-rules:begin -->` / `<\!-- nrg:agent-rules:end -->` and keeps the rest of the file; with `--check` it exits `1` and prints a diff when the block is out of date. Closes [#75](https://github.com/nanolaba/readme-generator/issues/75).<!--en-->
- **`--agent-rules`**: печатает блок инструкций для `AGENTS.md` / `CLAUDE.md`, вычисленный по шаблонам, — сгенерированные файлы и их шаблоны, фрагменты для правки, исходники, встроенные в документацию, языки и точные команды проверки и генерации (`./nrgw`, если есть обёртка). `--write AGENTS.md` вставляет или заменяет блок между `<\!-- nrg:agent-rules:begin -->` / `<\!-- nrg:agent-rules:end -->`, не трогая остальной файл; с `--check` завершается с кодом `1` и печатает diff, если блок устарел. Закрывает [#75](https://github.com/nanolaba/readme-generator/issues/75).<!--ru-->
- **Claude Code plugin, Agent Skill, syntax card and `llms.txt`**: the repository is now a Claude Code plugin marketplace (`/plugin marketplace add nanolaba/readme-generator`, `/plugin install nrg@nanolaba`). The plugin ships the NRG Agent Skill (`skills/nrg/SKILL.md`) with a one-page syntax card (`skills/nrg/SYNTAX.md`, generated by NRG from the widget documentation, so it follows the README), and hooks built on the new `--claude-hook pre-edit|post-edit`: an edit of a generated file is refused with the name of its template, and an edited template is validated and regenerated. `nrg --help syntax` prints the card bundled with the installed version; `llms.txt` points language models to the docs. Closes [#76](https://github.com/nanolaba/readme-generator/issues/76).<!--en-->
- **Плагин для Claude Code, Agent Skill, шпаргалка по синтаксису и `llms.txt`**: репозиторий теперь ещё и маркетплейс плагинов Claude Code (`/plugin marketplace add nanolaba/readme-generator`, `/plugin install nrg@nanolaba`). Плагин содержит навык NRG (`skills/nrg/SKILL.md`) с одностраничной шпаргалкой (`skills/nrg/SYNTAX.md`, генерируется NRG из документации виджетов и потому не отстаёт от README) и хуки на основе новой опции `--claude-hook pre-edit|post-edit`: правка сгенерированного файла отклоняется с указанием его шаблона, а изменённый шаблон проверяется и перегенерируется. `nrg --help syntax` печатает шпаргалку, вложенную в установленную версию; `llms.txt` указывает языковым моделям путь к документации. Закрывает [#76](https://github.com/nanolaba/readme-generator/issues/76).<!--ru-->
- **`--sandbox`, `--no-env`, `--env-allow`, `--offline`** for templates you do not trust: `--no-env` hides every environment variable from `\${env.NAME}` (property values included; fallbacks still apply), `--env-allow NAME,PREFIX_*` exposes only the listed ones, `--offline` refuses remote imports even when the template sets `nrg.allowRemoteImports=true` (a `sha256`-pinned URL already in the cache still works), and `--sandbox` is both and rejects `--allow-exec`. Only the caller sets them — no template property can lift them. Maven plugin: `<sandbox>`, `<noEnv>`, `<envAllow>`, `<offline>`; GitHub Action: `sandbox` input. Closes [#77](https://github.com/nanolaba/readme-generator/issues/77).<!--en-->
- **`--sandbox`, `--no-env`, `--env-allow`, `--offline`** для шаблонов, которым вы не доверяете: `--no-env` скрывает от `\${env.NAME}` все переменные окружения (и в значениях свойств; fallback-значения работают), `--env-allow NAME,PREFIX_*` открывает только перечисленные, `--offline` отклоняет удалённый импорт, даже если шаблон задаёт `nrg.allowRemoteImports=true` (URL, закреплённый по `sha256` и уже лежащий в кэше, работает), а `--sandbox` включает оба режима и отклоняет `--allow-exec`. Их задаёт только вызывающая сторона — никакое свойство шаблона их не снимет. Maven-плагин: `<sandbox>`, `<noEnv>`, `<envAllow>`, `<offline>`; GitHub Action: вход `sandbox`. Закрывает [#77](https://github.com/nanolaba/readme-generator/issues/77).<!--ru-->
- **Output variants**: `<\!--@nrg.variants=agents,claude,copilot-->` generates one template once per variant and per language — `AGENTS.md`, `CLAUDE.md` and `.github/copilot-instructions.md` from one source, or a user and a developer edition of a guide. `<\!--variant:a,b-->` / `<\!--variant:!c-->` select lines, `\${nrg.variant}` names the current variant, file name patterns accept `<variant>` / `<VARIANT>`, `nrg.variant.<name>.file` sets one variant's file, and variants that would write the same file stop the run. `--stdout --variant <name>`, `--validate`, `--manifest`, `--is-generated` and `--locate` know about variants. Closes [#78](https://github.com/nanolaba/readme-generator/issues/78).<!--en-->
- **Варианты вывода**: `<\!--@nrg.variants=agents,claude,copilot-->` генерирует шаблон по разу для каждого варианта и каждого языка — `AGENTS.md`, `CLAUDE.md` и `.github/copilot-instructions.md` из одного источника или версии руководства для пользователей и разработчиков. `<\!--variant:a,b-->` / `<\!--variant:!c-->` отбирают строки, `\${nrg.variant}` называет текущий вариант, паттерны имён файлов понимают `<variant>` / `<VARIANT>`, `nrg.variant.<name>.file` задаёт файл одного варианта, а если два варианта пишут в один файл, запуск останавливается. Варианты поддерживают `--stdout --variant <name>`, `--validate`, `--manifest`, `--is-generated` и `--locate`. Закрывает [#78](https://github.com/nanolaba/readme-generator/issues/78).<!--ru-->

### 1.3<!--toc.ignore-->

- **`details` widget — collapsible `<details>` blocks**: new `\${widget:details(summary='…')}` … `\${widget:endDetails}` block widget rewrites paired markers into a GitHub-friendly `<details><summary>…</summary>…</details>` block, with the inner markdown still flowing through the normal pipeline — nested widgets, `\${var}` substitution, and language tags keep working inside. A single-tag shortcut `\${widget:details(summary='…', content='…')}` renders compact inline HTML for short snippets; `open='true'` emits `<details open>` in either form. Removes the need to hand-write HTML inside templates for the long-tables / verbose-troubleshooting / faq-section pattern. Stray `endDetails` and unclosed openers are recovered the same way as `if`/`endIf`. Closes [#31](https://github.com/nanolaba/readme-generator/issues/31).<!--en-->
- **Виджет `details` — сворачиваемые блоки `<details>`**: новый блочный виджет `\${widget:details(summary='…')}` … `\${widget:endDetails}` превращает парные маркеры в GitHub-совместимый блок `<details><summary>…</summary>…</details>`, при этом внутренний markdown по-прежнему проходит через основной пайплайн — вложенные виджеты, подстановка `\${var}` и языковые теги внутри продолжают работать. Однотеговый сокращённый вариант `\${widget:details(summary='…', content='…')}` рендерит компактный inline-HTML для коротких вставок; `open='true'` даёт `<details open>` в обеих формах. Снимает необходимость руками писать HTML в шаблонах для типового сценария «длинная таблица / подробный troubleshooting / FAQ-секция». Одинокий `endDetails` и незакрытый открывающий тег восстанавливаются по той же схеме, что у `if`/`endIf`. Закрывает [#31](https://github.com/nanolaba/readme-generator/issues/31).<!--ru-->
- **`if` widget — new inline form**: `\${widget:if(cond='…', text='…')}` emits `text` on a single line when `cond` is truthy, and empty string otherwise — useful for short conditional snippets where the existing block form (`\${widget:if(cond='…')}` … `\${widget:endIf}`) is overkill. `\n` and `\\` inside `text=` are interpreted, and property / language substitution against the outer template happens before the widget runs. The block form is unchanged. Internally, both forms now live on a unified `BlockWidget` base class shared with `details`; the standalone `IfBlockProcessor` / `DetailsBlockProcessor` classes are removed (no user-visible effect — internal refactor).<!--en-->
- **Виджет `if` — новая однотеговая форма**: `\${widget:if(cond='…', text='…')}` выдаёт `text` одной строкой при истинном условии, либо пустую строку — удобно для коротких условных вставок, когда полноценная блочная форма (`\${widget:if(cond='…')}` … `\${widget:endIf}`) избыточна. `\n` и `\\` внутри `text=` интерпретируются, подстановка переменных и языковых конструкций внешнего шаблона выполняется до запуска виджета. Блочная форма не изменилась. Внутренне обе формы теперь живут на едином базовом классе `BlockWidget`, общем с `details`; standalone-классы `IfBlockProcessor` / `DetailsBlockProcessor` удалены (без user-visible эффекта — внутренний рефакторинг).<!--ru-->
- **`toc` short alias for `tableOfContents`**: `\${widget:toc(...)}` now works as a synonym for `\${widget:tableOfContents(...)}` — anchor generation, parameters, and rendered output are byte-identical. Primary name stays `tableOfContents`. Aliases are a general widget-system feature: third-party widgets can declare their own via the new `NRGWidget.getAliases()` default method.<!--en-->
- **Короткий алиас `toc` для `tableOfContents`**: `\${widget:toc(...)}` теперь работает как синоним `\${widget:tableOfContents(...)}` — генерация якорей, параметры и итоговый вывод побайтно совпадают. Основным именем остаётся `tableOfContents`. Алиасы — общая возможность системы виджетов: сторонние виджеты могут декларировать свои через новый default-метод `NRGWidget.getAliases()`.<!--ru-->
- **Parentheses inside quoted widget parameters**: a `)` inside a quoted parameter value no longer ends the widget tag. The documented `\${widget:if(cond='endsWith(\${devVersion}, -SNAPSHOT)')}` / `startsWith(...)` conditions and `(…)` grouping now work in both the block and the inline form — previously the opener was left in the output as literal text, the block body was always rendered and every `\${widget:endIf}` was reported as stray. The same fix lets `math` take `expr='f(x) = (a + b)^2'`, `details` take `summary='Advanced (optional)'`, and `--validate` see such tags. Closes [#55](https://github.com/nanolaba/readme-generator/issues/55).<!--en-->
- **Круглые скобки внутри параметров виджета в кавычках**: `)` внутри значения параметра в кавычках больше не обрывает тег виджета. Описанные в документации условия `\${widget:if(cond='endsWith(\${devVersion}, -SNAPSHOT)')}` / `startsWith(...)` и группировка `(…)` теперь работают и в блочной, и в однотеговой форме — раньше открывающий тег оставался в выводе как текст, тело блока рендерилось всегда, а каждый `\${widget:endIf}` считался одиноким. То же исправление позволяет писать `expr='f(x) = (a + b)^2'` в `math`, `summary='Advanced (optional)'` в `details` и делает такие теги видимыми для `--validate`. Закрывает [#55](https://github.com/nanolaba/readme-generator/issues/55).<!--ru-->
- **`tableOfContents` no longer loses headings after a fence line with a language marker**: a closing fence followed by a language marker — hand-written (`` ```<\!--en--> ``) or produced by `\${widget:import(..., wrap='true')}` on a line tagged `<\!--en-->` / `<\!--ru-->` — was not recognised as a closer, so the next fence flipped the state and every later heading was silently dropped from the table of contents. Fences are now matched on the line as it appears in the generated file. Closes [#56](https://github.com/nanolaba/readme-generator/issues/56).<!--en-->
- **`tableOfContents` больше не теряет заголовки после строки-ограды с языковым маркером**: закрывающая ограда блока кода, за которой идёт языковой маркер — написанная вручную (`` ```<\!--en--> ``) или порождённая `\${widget:import(..., wrap='true')}` в строке с `<\!--en-->` / `<\!--ru-->`, — не распознавалась как закрывающая, из-за чего следующая ограда переворачивала состояние и все последующие заголовки молча пропадали из оглавления. Теперь ограды сопоставляются по строке в том виде, в каком она попадёт в сгенерированный файл. Закрывает [#56](https://github.com/nanolaba/readme-generator/issues/56).<!--ru-->
- **Multi-line widget output keeps the indentation of the widget line**: a widget placed on an indented line (typically inside a list item) used to indent only the first line of its output — for `\${widget:import(..., wrap='true')}` that meant an indented opening fence followed by code and a closing fence at column 0, which broke the list in Markdown renderers. Every non-blank line of the output is now prefixed with the leading spaces / tabs of the widget line; this applies to all widgets (`import`, `alert`, `fileTree`, `exec`, `tableOfContents`, custom ones). Output changes only for templates that already had a multi-line widget on an indented line. Closes [#57](https://github.com/nanolaba/readme-generator/issues/57).<!--en-->
- **Многострочный вывод виджета сохраняет отступ строки виджета**: у виджета в строке с отступом (обычно внутри элемента списка) отступ получала только первая строка вывода — для `\${widget:import(..., wrap='true')}` это давало открывающую ограду с отступом, а код и закрывающую ограду с нулевой колонки, что ломало список в Markdown-рендерерах. Теперь каждая непустая строка вывода получает ведущие пробелы / табы строки виджета; это относится ко всем виджетам (`import`, `alert`, `fileTree`, `exec`, `tableOfContents`, пользовательские). Вывод меняется только у шаблонов, где многострочный виджет уже стоял в строке с отступом. Закрывает [#57](https://github.com/nanolaba/readme-generator/issues/57).<!--ru-->
- **`import` with `heading-offset` no longer mis-shifts after a fence line with a language marker**: the same fence-matching fix as for `tableOfContents` — in an imported `.src.md`, a closing fence written as `` ```<\!--en--> `` was not recognised, so headings after it were left unshifted and `#` lines inside the next code block were shifted instead.<!--en-->
- **`import` с `heading-offset` больше не ошибается после строки-ограды с языковым маркером**: то же исправление сопоставления оград, что и для `tableOfContents` — в импортируемом `.src.md` закрывающая ограда вида `` ```<\!--en--> `` не распознавалась, из-за чего заголовки после неё не сдвигались, а строки с `#` внутри следующего блока кода, наоборот, сдвигались.<!--ru-->
- **Security: a template can no longer write files outside the project**: `nrg.fileNamePattern` (and its per-language / default-language variants) accepted `../`, so a template could create or overwrite any file the process could write — with `nrg.noHeader` the content was fully template-controlled, which amounted to running code without `--allow-exec`. Output files must now stay inside the **project root**: the nearest ancestor of the source file that contains `.git`, or the source file's directory when there is none. A pattern that leaves it fails the run (also in `--check` and `--stdout`) and nothing is written. New `--root <dir>` CLI option, `<root>` Maven plugin parameter and `root` GitHub Action input widen the root for layouts that need it; the root cannot be set from a template.<!--en-->
- **Безопасность: шаблон больше не может писать файлы за пределами проекта**: `nrg.fileNamePattern` (и его варианты для отдельного языка / языка по умолчанию) принимал `../`, поэтому шаблон мог создать или перезаписать любой файл, доступный процессу на запись, — а с `nrg.noHeader` содержимое полностью задавалось шаблоном, что равносильно запуску кода без `--allow-exec`. Теперь выходные файлы должны оставаться внутри **корня проекта**: ближайшего предка исходного файла, содержащего `.git`, либо каталога исходного файла, если такого предка нет. Паттерн, выводящий за корень, завершает запуск ошибкой (в том числе в `--check` и `--stdout`), и ничего не записывается. Новая CLI-опция `--root <dir>`, параметр `<root>` Maven-плагина и вход `root` GitHub Action расширяют корень для раскладок, которым это нужно; из шаблона корень задать нельзя.<!--ru-->
- **Security: XML external entities are no longer resolved when reading a POM**: the file behind `\${pom.*}` is chosen by the template (`nrg.pom.path`), and it was parsed with the JDK defaults — an external entity could pull the content of any local file into the output or open a network connection without `nrg.allowRemoteImports`. A document that declares a `DOCTYPE` is now refused as a whole (`pom reader: failed to parse …`, every `\${pom.*}` renders empty). Ordinary `pom.xml` files have no `DOCTYPE` and are unaffected.<!--en-->
- **Безопасность: при чтении POM больше не раскрываются внешние XML-сущности**: файл, из которого берутся `\${pom.*}`, выбирается шаблоном (`nrg.pom.path`), а разбирался он с настройками JDK по умолчанию — внешняя сущность могла подтянуть в вывод содержимое любого локального файла или открыть сетевое соединение без `nrg.allowRemoteImports`. Документ с объявлением `DOCTYPE` теперь отклоняется целиком (`pom reader: failed to parse …`, все `\${pom.*}` рендерятся пустыми). Обычные `pom.xml` не содержат `DOCTYPE`, и их это не затрагивает.<!--ru-->
- **Security: a template can no longer read files outside the project**: `\${widget:import(path='../../…')}`, `\${widget:fileTree(path=…)}` (absolute paths included) and the `nrg.pom.path` / `nrg.npm.path` / `nrg.gradle.path` properties reached any file the process could read and copied it into the generated output — for example signing passwords from a `gradle.properties` outside the repository. These paths are now held to the same project root as output files; a path outside it fails the run, and `--validate` reports an escaping import as an error without opening the file. **Behaviour change:** a template that is *not* inside a git repository can no longer import from a parent directory unless `--root` names a wider root; inside a git repository, `../` keeps working as long as it stays in the repository.<!--en-->
- **Безопасность: шаблон больше не может читать файлы за пределами проекта**: `\${widget:import(path='../../…')}`, `\${widget:fileTree(path=…)}` (включая абсолютные пути) и свойства `nrg.pom.path` / `nrg.npm.path` / `nrg.gradle.path` дотягивались до любого файла, доступного процессу на чтение, и копировали его в сгенерированный вывод — например, пароли подписи из `gradle.properties` вне репозитория. Теперь для этих путей действует тот же корень проекта, что и для выходных файлов: путь за его пределами завершает запуск ошибкой, а `--validate` сообщает о таком импорте как об ошибке, не открывая файл. **Изменение поведения:** шаблон, лежащий *не* в git-репозитории, больше не может импортировать из родительского каталога, пока `--root` не задаст более широкий корень; внутри git-репозитория `../` работает как прежде, пока путь остаётся в репозитории.<!--ru-->
- **Security: a remote template must be pinned**: `\${widget:import(url='…')}` renders the fetched text as a template when `run-generator='true'` — the default for URLs ending in `.src.md` — and a template can import local files and read descriptors and environment variables. Without a `sha256` pin, whoever controlled the URL or the connection controlled what was read from the build machine into the README. Such an import now fails with a message asking for `sha256='…'` or `run-generator='false'` (embed as plain text). **Behaviour change** for templates that import a remote `.src.md` without `sha256`.<!--en-->
- **Безопасность: удалённый шаблон должен быть закреплён**: `\${widget:import(url='…')}` рендерит загруженный текст как шаблон при `run-generator='true'` — это значение по умолчанию для URL, оканчивающихся на `.src.md`, — а шаблон может импортировать локальные файлы, читать дескрипторы и переменные окружения. Без закрепления по `sha256` тот, кто контролировал URL или соединение, контролировал и то, что читается с машины сборки в README. Теперь такой импорт завершается ошибкой с просьбой указать `sha256='…'` или `run-generator='false'` (вставка как обычного текста). **Изменение поведения** для шаблонов, импортирующих удалённый `.src.md` без `sha256`.<!--ru-->
- **Hardened HTTP client for remote imports**: a redirect to a non-`http(s)` URL is refused with a clear error (it used to crash with a `ClassCastException`), as is a redirect from `https` down to `http`; a response larger than 16 MiB is refused instead of being buffered without limit; `timeout` now bounds the whole exchange, so a server that drips data cannot hold the build forever; `timeout='30d'` and other values above ~24 days no longer fail with `timeouts can't be negative`; fetching over plain `http://` without `sha256` logs a warning.<!--en-->
- **Усиленный HTTP-клиент удалённого импорта**: редирект на адрес не по `http(s)` отклоняется с понятной ошибкой (раньше падал с `ClassCastException`), как и редирект с `https` на `http`; ответ больше 16 МиБ отклоняется, а не буферизуется без ограничений; `timeout` теперь ограничивает весь обмен, так что сервер, отдающий данные по капле, не может удерживать сборку бесконечно; `timeout='30d'` и другие значения больше ~24 дней больше не падают с `timeouts can't be negative`; загрузка по обычному `http://` без `sha256` сопровождается предупреждением.<!--ru-->
- **Long text inside `\${en:'…', ru:'…'}` no longer crashes generation**: a quoted text of roughly two thousand characters or more ended the run with `StackOverflowError`. Any length works now, as does any number of doubled quotes.<!--en-->
- **Длинный текст внутри `\${en:'…', ru:'…'}` больше не роняет генерацию**: текст в кавычках длиной примерно от двух тысяч символов завершал запуск ошибкой `StackOverflowError`. Теперь работает любая длина, как и любое число удвоенных кавычек.<!--ru-->
- **A property comment no longer swallows the rest of its line**: `<\!--\@key=value-->` was removed from the output together with everything up to the *last* `-->` on the line, so in `A <\!--\@p=1--> text <\!-- note --> tail` the words `text` and the note silently disappeared; and a line that began with a property comment was dropped entirely when a second comment followed the text — or when the text contained no ASCII letters at all, which hit every non-Latin language (`<\!--\@p=1--> Привет` produced nothing). Each property comment is now removed on its own, and a line is skipped only when nothing but property definitions is on it.<!--en-->
- **Комментарий-свойство больше не съедает остаток строки**: `<\!--\@key=value-->` удалялся из вывода вместе со всем, что стояло до *последнего* `-->` в строке, поэтому в `A <\!--\@p=1--> text <\!-- note --> tail` слово `text` и заметка молча пропадали; а строка, начинавшаяся с комментария-свойства, выбрасывалась целиком, если после текста шёл второй комментарий — или если в тексте не было ни одной ASCII-буквы, то есть для любого нелатинского языка (`<\!--\@p=1--> Привет` не давал ничего). Теперь каждый комментарий-свойство удаляется сам по себе, а строка пропускается, только если на ней нет ничего, кроме определений свойств.<!--ru-->
- **Circular imports are reported**: a template that imports itself — directly or through other files — used to recurse until the stack overflowed; the error was logged and the run still exited with code 0, leaving a broken output file. It now fails immediately with `import: circular import: a.src.md -> b.src.md -> a.src.md`. Importing the same file twice, or a region of the importing file itself, is still fine.<!--en-->
- **Циклические импорты обнаруживаются**: шаблон, импортирующий сам себя — напрямую или через другие файлы, — раньше рекурсивно разворачивался до переполнения стека; ошибка писалась в журнал, а запуск всё равно завершался с кодом 0, оставляя испорченный выходной файл. Теперь он сразу завершается ошибкой `import: circular import: a.src.md -> b.src.md -> a.src.md`. Импортировать один и тот же файл дважды или регион самого импортирующего файла по-прежнему можно.<!--ru-->
- **Hostile or accidental extremes no longer crash or stall generation**: an `if` condition nested deeper than 64 levels and a `package.json` nested deeper than 512 are reported as ordinary errors instead of ending the run with `StackOverflowError`; a very long widget parameter (hundreds of kilobytes on one line) is parsed in linear time instead of taking minutes; so is a line with thousands of unterminated `<\!--\@` markers.<!--en-->
- **Экстремальные входные данные — злонамеренные или случайные — больше не роняют и не подвешивают генерацию**: условие `if` с вложенностью глубже 64 уровней и `package.json` с вложенностью глубже 512 сообщаются как обычные ошибки, а не завершают запуск с `StackOverflowError`; очень длинный параметр виджета (сотни килобайт в одной строке) разбирается за линейное время вместо минут; то же касается строки с тысячами незакрытых маркеров `<\!--\@`.<!--ru-->
- **GitHub Action verifies the NRG release it downloads**: new `nrg-sha256` input pins the expected checksum of the release zip — a mismatch fails the run before the jar is executed. Without it the action checks the download against the `.sha256` file now published with each release, and for older releases prints the checksum so it can be pinned.<!--en-->
- **GitHub Action проверяет скачиваемый релиз NRG**: новый вход `nrg-sha256` закрепляет ожидаемую контрольную сумму релизного zip — несовпадение завершает запуск до исполнения jar. Без него action сверяет загрузку с файлом `.sha256`, который теперь публикуется с каждым релизом, а для более старых релизов печатает контрольную сумму, чтобы её можно было закрепить.<!--ru-->
- **`exec` widget no longer times out on large output**: the command's output was read only after the process had finished, but a process that writes more than the operating system's pipe buffer (a few kilobytes) blocks until someone reads — so every command with sizeable stdout or stderr hung until the timeout and produced nothing. Both streams are now read while the command runs, and the command's standard input is closed, so a program that waits for input ends immediately instead of hanging.<!--en-->
- **Виджет `exec` больше не уходит в таймаут на большом выводе**: вывод команды читался только после завершения процесса, но процесс, пишущий больше буфера канала операционной системы (несколько килобайт), блокируется, пока его не прочитают, — поэтому любая команда с объёмным stdout или stderr висела до таймаута и не давала ничего. Теперь оба потока читаются во время работы команды, а стандартный ввод команды закрыт, так что программа, ожидающая ввода, завершается сразу, а не зависает.<!--ru-->
- **Imported files and the table of contents now see what the main template sees**: a custom widget registered with `--widgets`, `<widgets>`, `NRG.addWidget(...)` or the root template's `nrg.widgets` was unknown inside an imported file (the tag was left in the output as text); `exec` inside an imported local file was refused even with `--allow-exec`; and a document with a table of contents logged `Unknown widget name` and `exec widget: execution is disabled` for widgets that worked fine, because the table of contents scans the document in a second pass that had none of this. All of it is passed down now. A `tableOfContents` inside an imported file no longer fails with a `NullPointerException` for languages other than the first, and `exec` is no longer attempted in the scan pass at all.<!--en-->
- **Импортируемые файлы и оглавление теперь видят то же, что и основной шаблон**: пользовательский виджет, зарегистрированный через `--widgets`, `<widgets>`, `NRG.addWidget(...)` или `nrg.widgets` корневого шаблона, был неизвестен внутри импортируемого файла (тег оставался в выводе как текст); `exec` внутри импортируемого локального файла отклонялся даже с `--allow-exec`; а документ с оглавлением писал в журнал `Unknown widget name` и `exec widget: execution is disabled` для исправно работающих виджетов — потому что оглавление сканирует документ вторым проходом, которому всё это не передавалось. Теперь передаётся. `tableOfContents` внутри импортируемого файла больше не падает с `NullPointerException` для языков, кроме первого, а `exec` в сканирующем проходе вообще не запускается.<!--ru-->
- **Widget parameters no longer need a space after the comma**: in `\${widget:tableOfContents(title="T",ordered="true")}` both parameters were silently ignored, because everything up to the last `=` — `title="T",ordered` — was read as a single parameter name. A name now ends at a comma, `=` or quote, so `a='1',b='2'` means the same as `a='1', b='2'`. Parameter lists written with spaces are parsed exactly as before.<!--en-->
- **Параметрам виджета больше не нужен пробел после запятой**: в `\${widget:tableOfContents(title="T",ordered="true")}` оба параметра молча игнорировались, потому что всё до последнего `=` — `title="T",ordered` — читалось как одно имя параметра. Теперь имя заканчивается на запятой, `=` или кавычке, поэтому `a='1',b='2'` означает то же, что `a='1', b='2'`. Списки параметров, записанные с пробелами, разбираются в точности как раньше.<!--ru-->

### 1.2<!--toc.ignore-->

- **Scope `--check` to specific files**: new `--check-paths` CLI flag, `<checkPaths>` Maven plugin parameter, and `check-paths` GitHub Action input limit drift detection to outputs matching the supplied `glob:` patterns (literal paths or globs, repeatable). Useful for the "only the canonical README is tracked, translations are regenerated by a bot" workflow — currently the choice is "commit every generated file" (drift-check works) or "commit none" (drift-check unusable). Patterns are cwd-relative, follow the same `**/` semantics as multi-file source globs, and a typoed path that matches nothing emits a stderr WARN so silent misconfiguration is visible. `--check-paths` requires `--check`; without the filter, every declared language is checked as before. Closes [#53](https://github.com/nanolaba/readme-generator/issues/53).<!--en-->
- **Ограничение `--check` отдельными файлами**: новый CLI-флаг `--check-paths`, парный параметр `<checkPaths>` Maven-плагина и вход `check-paths` GitHub-action-а сужают drift-проверку до выходных файлов, попадающих под указанные `glob:`-шаблоны (литералы или маски, повторяемый). Полезно для сценария «в git лежит только канонический README, а переводы регенерируются ботом» — сейчас выбор стоит между «коммитить все сгенерированные файлы» (drift-check работает) и «не коммитить ничего» (drift-check бесполезен). Шаблоны разрешаются относительно cwd, поддерживают ту же семантику `**/`, что и мульти-файловые исходные glob-ы, а опечатка в пути, не совпавшая ни с одним выходом, печатает WARN в stderr — тихая мисконфигурация становится видимой. `--check-paths` требует `--check`; без фильтра проверяется каждый объявленный язык, как и раньше. Закрывает [#53](https://github.com/nanolaba/readme-generator/issues/53).<!--ru-->
- **Customisable head comment**: new `--no-header` CLI flag (and matching `<noHeader>true</noHeader>` Maven plugin parameter) suppresses the auto-generated two-line `<\!-- This file was automatically generated... -->` block at the top of every output file; `--header-text "..."` (`<headerText>...</headerText>`) replaces it with arbitrary text — `\n`, `\r`, `\t`, `\\` are interpreted, so a multi-line custom header is one flag away. The two flags are mutually exclusive. Equivalent template properties `<\!--\@nrg.noHeader=true-->` and `<\!--\@nrg.headerText=...-->` work identically; CLI / Maven values win on conflict. Lets maintainers running their own auto-doc tooling (e.g. per-file `@LastEditTime` HTML comments) opt out of NRG's signature without forking the generation step. Closes [#51](https://github.com/nanolaba/readme-generator/issues/51).<!--en-->
- **Настраиваемый head-комментарий**: новый CLI-флаг `--no-header` (и парный параметр `<noHeader>true</noHeader>` Maven-плагина) убирает автоматический двухстрочный блок `<\!-- This file was automatically generated... -->` из каждого выходного файла; `--header-text "..."` (`<headerText>...</headerText>`) заменяет его произвольным текстом — `\n`, `\r`, `\t`, `\\` интерпретируются, так что многострочный кастомный заголовок задаётся одним флагом. Флаги взаимно исключающие. Эквивалентные свойства шаблона `<\!--\@nrg.noHeader=true-->` и `<\!--\@nrg.headerText=...-->` работают аналогично; значения из CLI / Maven побеждают при конфликте. Позволяет мейнтейнерам, использующим собственный auto-doc (например, по-файловые `@LastEditTime` HTML-комментарии), отказаться от подписи NRG без форка шага генерации. Закрывает [#51](https://github.com/nanolaba/readme-generator/issues/51).<!--ru-->
- **`badge` widget — optional `alt=` parameter**: every type (`maven-central`, `license`, `github-release`, `github-stars`, `github-workflow`, `custom`) now accepts an optional `alt='...'` that overrides the auto-derived Markdown alt-text without changing the visible badge label rendered by shields.io. Useful for SEO and screen-reader accessibility — phrase-style alts like `NRG continuous integration build status` carry semantic signal that bare `CI` does not. Empty `alt=''` falls back to the type's default. Closes [#52](https://github.com/nanolaba/readme-generator/issues/52).<!--en-->
- **Виджет `badge` — необязательный параметр `alt=`**: каждый тип (`maven-central`, `license`, `github-release`, `github-stars`, `github-workflow`, `custom`) теперь принимает опциональный `alt='...'`, переопределяющий автоматический alt-текст markdown-изображения без изменения видимой надписи на бейдже от shields.io. Полезно для SEO и доступности — фраза вроде `NRG continuous integration build status` несёт смысловую нагрузку, в отличие от короткой метки `CI`. Пустое `alt=''` приводит к значению по умолчанию. Закрывает [#52](https://github.com/nanolaba/readme-generator/issues/52).<!--ru-->
- **Preserve original line endings on regeneration**: NRG now detects the existing on-disk output file's CRLF/LF convention and writes the regenerated content with the same convention, instead of always emitting `System.lineSeparator()`. Mixed-ending files normalise to LF. New CLI flag `--line-ending=auto|lf|crlf` (default `auto`) and matching Maven plugin `<lineEnding>` parameter override detection. In `--check` mode, `auto` ignores LE-only differences so a CRLF-vs-LF contributor mismatch no longer trips CI; explicit `lf` / `crlf` still flag a mismatch (that's the explicitly-requested invariant). Closes [#48](https://github.com/nanolaba/readme-generator/issues/48).<!--en-->
- **Сохранение оригинальных переводов строк при перегенерации**: NRG определяет конвенцию CRLF/LF существующего на диске выходного файла и записывает свежий результат в той же конвенции, а не всегда платформенным `System.lineSeparator()`. Файлы со смешанными переводами нормализуются в LF. Новый CLI-флаг `--line-ending=auto|lf|crlf` (по умолчанию `auto`) и парный параметр `<lineEnding>` Maven-плагина переопределяют автодетект. В режиме `--check` `auto` игнорирует расхождения только по переводам строк — рассинхрон CRLF/LF между контрибьюторами больше не валит CI; явные `lf` / `crlf` по-прежнему отмечают несовпадение (это явно затребованный инвариант). Закрывает [#48](https://github.com/nanolaba/readme-generator/issues/48).<!--ru-->
- **`nrg-maven-plugin` no longer inherits its `create-files` execution into child modules by default**: the goal is declared with `inheritByDefault = false`, so multi-module (aggregator) builds run README generation only at the root POM where `README.src.md` lives — child modules no longer re-invoke NRG in their own directory and spam warnings (or fail) over a missing source file. Soft-breaking only for projects that intentionally relied on per-child re-execution; opt back in with `<inherited>true</inherited>` in the child's POM. Closes [#49](https://github.com/nanolaba/readme-generator/issues/49).<!--en-->
- **`nrg-maven-plugin` больше не наследует `create-files` в дочерние модули по умолчанию**: цель объявлена с `inheritByDefault = false`, и в многомодульных (aggregator) сборках генерация README выполняется только в корневом POM, где лежит `README.src.md` — дочерние модули больше не вызывают NRG в своём каталоге и не сыпят предупреждения (или падают) из-за отсутствующего исходника. Мягкое breaking-изменение только для проектов, сознательно полагавшихся на повторный запуск в каждом модуле; верните прежнее поведение через `<inherited>true</inherited>` в POM-е модуля. Закрывает [#49](https://github.com/nanolaba/readme-generator/issues/49).<!--ru-->
- **`tableOfContents` widget — `numbering-style` and `start` parameters**: when `ordered='true'`, pick a counter shape from nine values — `default` (today's `1.` markers, byte-identical to omitting the parameter), hierarchical `dotted` (`1`, `1.1`, `1.1.1`), `legal` (`1.`, `1.1.`, `1.1.1.`), `appendix` (`A`, `A.1`, `A.1.1`), or flat global counters `arabic` / `roman` / `roman-upper` / `alpha` / `alpha-upper`. Optional `start='3'` (or `'C'` for letter-based styles) seeds the top-level counter, useful for appendices following a numbered main body. `min-depth` clipping renumbers from the visible top, so dropping shallow levels never leaves dangling sub-counters. Unknown values log an error and fall back to `default` — typos won't blank out the TOC. Closes [#43](https://github.com/nanolaba/readme-generator/issues/43).<!--en-->
- **Виджет `tableOfContents` — параметры `numbering-style` и `start`**: при `ordered='true'` выбирается форма счётчика из девяти значений — `default` (текущие маркеры `1.`, побайтно совпадает с пропуском параметра), иерархические `dotted` (`1`, `1.1`, `1.1.1`), `legal` (`1.`, `1.1.`, `1.1.1.`), `appendix` (`A`, `A.1`, `A.1.1`) или плоские глобальные счётчики `arabic` / `roman` / `roman-upper` / `alpha` / `alpha-upper`. Опциональный `start='3'` (или `'C'` для буквенных стилей) задаёт начальное значение верхнего уровня — удобно для приложений, идущих после нумерованного основного раздела. Отсечение по `min-depth` перенумеровывает с видимой вершины, так что отбрасывание неглубоких уровней не оставляет «висячих» подсчётчиков. При неизвестном значении в лог пишется ошибка и используется `default` — опечатка не обнуляет TOC. Закрывает [#43](https://github.com/nanolaba/readme-generator/issues/43).<!--ru-->

### 1.1<!--toc.ignore-->

- **Multi-file source input**: the CLI now accepts multiple positional source files and `glob:` patterns (`nrg "docs/**/*.src.md" A.src.md B.src.md`); `-f` remains a single-file alias and is rejected when mixed with positional args. Each input gets its own `Generator`. New `--fail-fast` short-circuits on the first non-zero per-file result; the default aggregates so every file's diagnostics surface in one run. With `--stdout`, per-file separators are emitted whenever the total output count exceeds one. Empty per-pattern matches log a warning; an overall zero-match exits `1`. The Maven plugin's `<file>` entries accept the same glob syntax, and a new `<failFast>` parameter (default `false`) maps to `--fail-fast`. Closes [#32](https://github.com/nanolaba/readme-generator/issues/32).<!--en-->
- **Множественный ввод исходных файлов**: CLI принимает несколько позиционных аргументов и `glob:`-паттернов (`nrg "docs/**/*.src.md" A.src.md B.src.md`); `-f` остаётся синонимом для одиночного файла и отклоняется при смешении с позиционными аргументами. Каждый файл получает собственный `Generator`. Новый флаг `--fail-fast` прерывает обработку на первом ненулевом результате; по умолчанию диагностики всех файлов выводятся в одном прогоне. В режиме `--stdout` появляются разделители между файлами, если выводов больше одного. Пустое сопоставление отдельного паттерна логируется как warning; общий ноль совпадений — выход `1`. Записи `<file>` Maven-плагина принимают тот же glob-синтаксис; добавлен параметр `<failFast>` (по умолчанию `false`), отображаемый на `--fail-fast`. Закрывает [#32](https://github.com/nanolaba/readme-generator/issues/32).<!--ru-->
- **Frozen regions**: `<\!--nrg.freeze id="..."-->` … `<\!--/nrg.freeze-->` block markers preserve content written by external tools (contributors-action, sponsors widgets, RSS embedders) into the generated readme across NRG regenerations. The template body between markers is a one-time bootstrap placeholder used only when the on-disk output file does not yet exist; subsequent regenerations splice the on-disk content back in. Optional `source-lang="X"` attribute redirects every language's freeze content to one source language's output file. Authoring errors (missing/duplicate id, unbalanced or nested markers, `source-lang` outside `nrg.languages`, unknown attributes) fail the build with exit `1` and are reported by `--validate`. On-disk anomalies (malformed blocks, missing ids) emit a one-time WARN and fall back to the template placeholder. Closes [#41](https://github.com/nanolaba/readme-generator/issues/41).<!--en-->
- **Замороженные регионы**: блочные маркеры `<\!--nrg.freeze id="..."-->` … `<\!--/nrg.freeze-->` сохраняют содержимое, записанное внешними инструментами (contributors-action, sponsors-виджеты, RSS-вставки) в сгенерированный readme, между перегенерациями NRG. Тело шаблона между маркерами — одноразовый bootstrap-плейсхолдер, используемый только когда файла на диске ещё нет; последующие перегенерации вставляют обратно содержимое с диска. Необязательный атрибут `source-lang="X"` перенаправляет содержимое frozen-блока для всех языков в выходной файл одного исходного языка. Ошибки автора (отсутствующий/дублирующийся id, несбалансированные или вложенные маркеры, `source-lang` вне `nrg.languages`, неизвестные атрибуты) прерывают сборку с кодом `1` и сообщаются `--validate`. Аномалии на диске (битые блоки, отсутствующие id) логируются как WARN однократно, далее используется bootstrap-плейсхолдер. Закрывает [#41](https://github.com/nanolaba/readme-generator/issues/41).<!--ru-->
- Fixed: the `tableOfContents` widget no longer treats `#`-prefixed lines inside fenced code blocks (` ``` ` / `~~~`), inline code spans, indented code blocks, or backslash-escaped headings as real headers, so ordered-list numbering and `getPreviousHeader()` are no longer poisoned by bash comments inside code samples. Closes [#46](https://github.com/nanolaba/readme-generator/issues/46).<!--en-->
- Исправлено: виджет `tableOfContents` больше не считает строки с префиксом `#` внутри fenced-блоков кода (` ``` ` / `~~~`), inline-кода, indented-блоков и backslash-escaped заголовков настоящими заголовками — нумерация ordered-list и `getPreviousHeader()` больше не ломаются bash-комментариями внутри примеров кода. Закрывает [#46](https://github.com/nanolaba/readme-generator/issues/46).<!--ru-->

- **`\${npm.NAME}` / `\${gradle.NAME}` substitution**: read values directly from `package.json` (dotted-path lookup like `\${npm.version}` or `\${npm.dependencies.lodash}`) and from `gradle.properties` + `build.gradle{,.kts}` (`\${gradle.version}`, `\${gradle.group}`, plus arbitrary keys from `gradle.properties`). Генерация прерывается, если два языка попадают в один и тот же файл. Виджет `languages` теперь формирует относительные ссылки, так что cross-directory раскладки работают.<!--ru-->

### 1.0<!--toc.ignore-->

- **`import` widget**: added the `lines`, `region`, `wrap`, `lang`, and `dedent` parameters for fine-grained inclusion of source files.<!--en-->
- Added `<\!--nrg.ignore-->` and paired `<\!--nrg.ignore.begin-->` / `<\!--nrg.ignore.end-->` markers for removing author notes from generated output (also inside imported files).<!--en-->
- **`tableOfContents` widget**: added the `min-depth` and `max-depth` parameters to limit which heading levels appear in the table of contents.<!--en-->
- **`tableOfContents` widget**: added the `min-items` parameter — the widget now skips rendering entirely (title included) when fewer than this many headings survive the filters.<!--en-->
- **`tableOfContents` widget**: added the `anchor-style` parameter (`github` | `gitlab` | `bitbucket`) to match the slugification rules of the target hosting platform.<!--en-->
- **Log levels**: added the `--log-level` CLI flag (`trace|debug|info|warn|error`, default `info`), the `NRG_LOG_LEVEL` environment variable fallback, and a matching `<logLevel>` Maven plugin parameter.<!--en-->
- **`--stdout` flag**: new CLI flag that streams generated output to standard output instead of writing files; pair with `--language <code>` to select a single variant.<!--en-->
- **Custom widgets from CLI and templates**: the `nrg.widgets` template property and the `--widgets` / `--classpath` CLI flags let users register custom `NRGWidget` implementations without a custom launcher.<!--en-->
- **Custom widgets in the Maven plugin**: the `nrg-maven-plugin` gains a `<widgets>` parameter; invalid entries fail the build with a descriptive `MojoExecutionException`. POM widgets override template-declared ones on name collision.<!--en-->
- Widget resolution now prefers the last registration on name collision, so user widgets shadow built-ins with the same name.<!--en-->
- **`--check` flag**: CI-friendly verification mode that compares generated output against files on disk, prints a diff to stderr on mismatch, and exits with status `1`. The `nrg-maven-plugin` exposes it via `<check>` and fails the build with a `MojoExecutionException`.<!--en-->
- **`alert` widget**: renders GitHub-flavored alert blocks (`> [!NOTE]`, `> [!WARNING]`, `> [!TIP]`, `> [!IMPORTANT]`, `> [!CAUTION]`) from a single `\${widget:alert(type='...', text='...')}` call, with `\n` escapes for multi-line body text.<!--en-->
- **`badge` widget**: renders shields.io badges for `maven-central`, `license`, `github-release`, `github-stars`, and a free-form `custom` variant — no more hand-crafted URLs.<!--en-->
- **`math` widget**: renders LaTeX formulas via GitHub's native `$…$` / `$$…$$` delimiters or as `![alt](…)` images through a LaTeX-to-SVG service (default: `latex.codecogs.com`).<!--en-->
- **`exec` widget (opt-in)**: runs an external command and embeds its stdout. Disabled by default; enable with `--allow-exec` (CLI) or `<allowExec>true</allowExec>` (Maven plugin). Supports `cwd`, `timeout`, `trim`, and `codeblock` parameters.<!--en-->
- **`\${env.NAME}` substitution**: read environment variables directly from any template position with shell-style defaults (`\${env.NAME:fallback}`). Works in body text, `<\!--@key=value-->` declaration values, and widget parameter values. Missing variables log a warning and render empty.<!--en-->
- **`\${pom.NAME}` substitution**: read values from the project `pom.xml` via a Maven-style dotted path (`\${pom.version}`, `\${pom.groupId}:\${pom.artifactId}`, `\${pom.parent.version}`, `\${pom.properties.java.version}`). Supports shell-style defaults, parent inheritance for `groupId` / `version` / `name`, and one-level POM-internal interpolation for `\${prop}`, `\${project.*}`, and `\${env.NAME}`. POM path defaults to the source-file directory; override via `<\!--\@nrg.pom.path=...-->`.<!--en-->
- **`if` block widget**: `\${widget:if(cond='…')}` … `\${widget:endIf}` conditionally drops a block of lines from the output. Supports a small string-only DSL: truthy / falsy, `==` / `!=`, `&&` / `||`, `!`, parentheses, and `startsWith` / `endsWith`. Two-phase evaluation (parse-then-resolve) keeps `${…}`-resolved values opaque, preventing operator injection. Inner widgets in dropped branches never execute.<!--en-->
- **`--validate` flag**: scans the source template and every reachable `\${widget:import}`-imported file for authoring mistakes (unknown widgets, undeclared language markers, missing import paths, unbalanced `<\!--nrg.ignore.begin-->` / `<\!--nrg.ignore.end-->` pairs) without generating any output. Exits `0` silently on a clean template, `1` with a `file:line: message` list otherwise. Mutually exclusive with `--check` and `--stdout`. The Maven plugin exposes it as `<validate>true</validate>` and fails the build with a `MojoExecutionException`.<!--en-->

Entries are sorted directories-first then alphabetically for stable byte-exact output.<!--en-->

Работает в основном тексте, в значениях `<\!--@key=value-->` и в параметрах виджетов. Отсутствующие переменные логируются как warning и подставляют пустую строку.<!--ru-->
- **Подстановка `\${pom.NAME}`**: чтение значений из проектного `pom.xml` по Maven-стилю dotted-path (`\${pom.version}`, `\${pom.groupId}:\${pom.artifactId}`, `\${pom.parent.version}`, `\${pom.properties.java.version}`). Поддерживает shell-стиль умолчаний, parent-наследование для `groupId` / `version` / `name`, и одноуровневую интерполяцию внутри POM-значений для `\${prop}`, `\${project.*}` и `\${env.NAME}`. - **Блочный виджет `if`**: `\${widget:if(cond='…')}` … `\${widget:endIf}` условно отбрасывает блок строк из вывода. Поддерживает компактный string-only DSL: truthy / falsy, `==` / `!=`, `&&` / `||`, `!`, скобки, `startsWith` / `endsWith`. Two-phase evaluation (parse-then-resolve) делает `${…}`-значения opaque, исключая operator-injection. Виджеты внутри отброшенных веток не выполняются.<!--ru-->
- **Флаг `--validate`**: сканирует исходный шаблон и все импортируемые через `\${widget:import}` файлы на типичные ошибки авторов (неизвестные виджеты, незаявленные языковые маркеры, отсутствующие пути импорта, несбалансированные пары `<\!--nrg.ignore.begin-->` / `<\!--nrg.ignore.end-->`) без генерации файлов. Чистый шаблон — выход `0` молча; иначе `1` со списком `file:line: message`. Несовместим с `--check` и `--stdout`. В Maven-плагине доступен как `<validate>true</validate>`; при наличии диагностик сборка падает с `MojoExecutionException`.<!--ru-->
- **Виджет `fileTree`**: формирует листинг каталога в стиле `tree -L` с Unicode-рамками. Поддерживает параметры `depth`, comma-separated `exclude`-globs (сопоставляются и с именем элемента, и с путём относительно `path`), `dirsOnly` и `codeblock`. Записи сортируются: сначала каталоги, потом файлы; внутри групп — по алфавиту, что даёт стабильный byte-exact вывод.<!--ru-->
