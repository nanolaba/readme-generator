## ${en:'Try it', ru:'Попробовать'}

Download `readme-generator-${stableVersion}.zip` from [the release page](https://github.com/nanolaba/readme-generator/releases/tag/v${stableVersion}) and unzip it; it needs only Java 8+. Then write `README.src.md`:<!--en-->
Скачайте `readme-generator-${stableVersion}.zip` со [страницы релиза](https://github.com/nanolaba/readme-generator/releases/tag/v${stableVersion}) и распакуйте; нужна только Java 8+. Затем напишите `README.src.md`:<!--ru-->

```markdown
<\!--@nrg.languages=en,ru-->

\${widget:languages}

# \${en:'Hello', ru:'Привет'}

Install with `make install`.<\!--en-->
Установка: `make install`.<\!--ru-->
```

```bash
nrg -f README.src.md
```

NRG writes `README.md` and `README.ru.md` next to the template. Here is `README.md`; `README.ru.md` is the same with the Russian lines:<!--en-->
NRG запишет рядом с шаблоном `README.md` и `README.ru.md`. Вот `README.md`; `README.ru.md` такой же, но с русскими строками:<!--ru-->

```markdown
<\!-- This file was automatically generated by Nanolaba Readme Generator (NRG) from README.src.md -->
<\!-- Do not edit it by hand: change README.src.md and regenerate. See https://github.com/nanolaba/readme-generator -->

[ **en** | [ru](README.ru.md) ]

# Hello

Install with `make install`.
```

The header names the template, so an agent that opens `README.md` first learns where the change belongs. If it edits `README.md` anyway, or changes the English line and leaves the Russian one, a command catches it:<!--en-->
Заголовок называет шаблон, и агент, открывший сначала `README.md`, узнаёт, где делать правку. Если он всё же поправит `README.md` или изменит английскую строку, не тронув русскую, это поймает команда:<!--ru-->

```text
$ nrg --check -f README.src.md
--- README.md (on disk)
+++ README.md (generated)
@@ line 8 @@
 
 # Hello
 
-Install with `make install PREFIX=~`.
+Install with `make install`.
 
Regenerate with: nrg -f /home/me/hello/README.src.md

$ nrg --stale-translations HEAD -f README.src.md
README.src.md:7-8: 'en' changed since HEAD, 'ru' did not
    en was: Install with `make install`.
    en now: Install with `make install PREFIX=~`.
Update the other languages, or mark an intentional one-sided edit with <\!--nrg.translation.ok-->
```

Both commands exit with `1`, so CI fails on either mistake. Under Claude Code the [plugin](#claude-code-plugin-and-the-nrg-skill) stops the edit of a generated file before it happens and hands the agent this message:<!--en-->
Обе команды завершаются с кодом `1`, и CI падает на любой из этих ошибок. В Claude Code [плагин](#плагин-для-claude-code-и-навык-nrg) останавливает правку сгенерированного файла ещё до того, как она случится, и отдаёт агенту такое сообщение:<!--ru-->

```text
README.ru.md is generated by NRG from README.src.md. Edit README.src.md (or the fragment it imports; nrg --locate README.ru.md:LINE names the line) and regenerate with: nrg -f README.src.md
```

More in [Quick start](#quick-start) and [Agent-driven development](#agent-driven-development).<!--en-->
Подробнее — в разделах [«Быстрый старт»](#быстрый-старт) и [«Агентная разработка»](#агентная-разработка).<!--ru-->

## ${en:'Why NRG', ru:'Зачем нужен NRG'}

- **One file to edit, not one per language.** Every language lives in one `.src.md`, each translation on the line next to its original, so an agent reads and edits them together and one diff shows both. Lines without a language marker are shared: code blocks, tables and links are written once. See [Multilanguage support](#multilanguage-support).<!--en-->
- **Один файл на правку, а не по файлу на язык.** Все языки лежат в одном `.src.md`, каждый перевод — на соседней строке с оригиналом: агент читает и правит их вместе, а один diff показывает оба. Строки без языкового маркера общие, так что блоки кода, таблицы и ссылки пишутся один раз. См. [«Поддержка нескольких языков»](#поддержка-нескольких-языков).<!--ru-->
- **Facts come from the build, not from memory.** `\${pom.version}`, `\${npm.version}` and `\${gradle.version}` are read from the build descriptor on every generation, and `\${widget:import(path='…', region='…')}` embeds a region of a source file that is compiled and tested. No version number in the README is typed by hand or recalled from memory. See [Maven POM values](#maven-pom-values) and [Widget 'import'](#widget-import).<!--en-->
- **Факты берутся из сборки, а не из памяти.** `\${pom.version}`, `\${npm.version}` и `\${gradle.version}` читаются из дескриптора сборки при каждой генерации, а `\${widget:import(path='…', region='…')}` вставляет регион исходника, который компилируется и проходит тесты. Ни один номер версии в README не набирается руками и не пишется по памяти. См. [«Значения из Maven POM»](#значения-из-maven-pom) и [«Виджет 'import'»](#виджет-import).<!--ru-->
- **A hand edit does not reach `main`.** `nrg --check` exits with `1` and prints a unified diff when a generated file differs from what its template produces; the GitHub Action does the same with `mode: check`. See [Verifying generated files](#verifying-generated-files-ci-mode).<!--en-->
- **Ручная правка не попадёт в `main`.** `nrg --check` завершается с кодом `1` и печатает unified diff, если сгенерированный файл отличается от того, что даёт шаблон; GitHub Action делает то же с `mode: check`. См. [«Проверка сгенерированных файлов»](#проверка-сгенерированных-файлов-режим-ci).<!--ru-->
- **The agent checks its own work.** `--validate` writes nothing and prints `ERROR: README.src.md:3: unknown widget 'language'; did you mean 'languages'?`. The exit code says what to do next: `1` regenerate, `2` fix the template, `64` fix the command. `--format json` returns the same diagnostics with a stable `code` and a `hint`. See [The agent loop](#the-agent-loop).<!--en-->
- **Агент сам проверяет свою работу.** `--validate` ничего не пишет и печатает `ERROR: README.src.md:3: unknown widget 'language'; did you mean 'languages'?`. Код возврата подсказывает следующий шаг: `1` — перегенерировать, `2` — исправить шаблон, `64` — исправить команду. С `--format json` те же диагностики приходят со стабильным `code` и подсказкой `hint`. См. [«Цикл работы агента»](#цикл-работы-агента).<!--ru-->
- **Translations that fell behind are listed.** `nrg --stale-translations origin/main` names every place where one language changed since that revision and another did not, with the old and the new text: the work list for updating the translation. See [Translations that fell behind](#translations-that-fell-behind).<!--en-->
- **Отставшие переводы видны списком.** `nrg --stale-translations origin/main` называет каждое место, где один язык изменился с этой ревизии, а другой нет, со старым и новым текстом — готовый список работы для обновления перевода. См. [«Отставшие переводы»](#отставшие-переводы).<!--ru-->
- **Agent instructions are generated too.** `nrg --agent-rules --write AGENTS.md` writes the block that tells an agent which files are generated, which templates to edit and which commands to run, from the real configuration; with `--check` CI keeps it current. See [Instructions for the agent](#instructions-for-the-agent).<!--en-->
- **Инструкции для агента тоже генерируются.** `nrg --agent-rules --write AGENTS.md` пишет по реальной конфигурации блок, который говорит агенту, какие файлы сгенерированы, какие шаблоны править и какие команды запускать; с `--check` CI следит, чтобы блок не устаревал. См. [«Инструкция для агента»](#инструкция-для-агента).<!--ru-->
- **A template is untrusted data.** Every path it names stays inside the project root, `exec` runs commands only with `--allow-exec`, and `--sandbox` hides environment variables and closes the network, for pull requests from strangers and agents that run unattended. See [Untrusted templates](#untrusted-templates).<!--en-->
- **Шаблон — недоверенные данные.** Любой путь, который он называет, остаётся внутри корня проекта, `exec` выполняет команды только с `--allow-exec`, а `--sandbox` скрывает переменные окружения и закрывает сеть — для pull request от незнакомцев и агентов, работающих без присмотра. См. [«Недоверенные шаблоны»](#недоверенные-шаблоны).<!--ru-->
- **Twelve widgets.** Table of contents, import of a file or a region, badges, `if` blocks, collapsible sections, alerts, LaTeX math, file trees, command output, dates, TODOs and the language switcher. A widget of your own is one Java class. See [Widgets](#widgets).<!--en-->
- **Двенадцать виджетов.** Оглавление, импорт файла или региона, бейджи, блоки `if`, сворачиваемые секции, alert-блоки, формулы LaTeX, дерево файлов, вывод команды, дата, TODO и переключатель языков. Свой виджет — это один Java-класс. См. [«Виджеты»](#виджеты).<!--ru-->
- **Output of other tools survives regeneration.** A frozen region keeps what contributors-readme-action, a sponsors widget or an RSS feed wrote into the generated file. See [Frozen regions](#frozen-regions).<!--en-->
- **Вывод других инструментов переживает перегенерацию.** Замороженная область сохраняет то, что contributors-readme-action, виджет спонсоров или RSS-лента записали в сгенерированный файл. См. [«Замороженные области»](#замороженные-области).<!--ru-->
- **The same NRG everywhere.** The `nrgw` wrapper pins a release and its sha256 in the repository, as `mvnw` does for Maven, so a contributor, a CI job and an agent in a fresh sandbox run the same version with nothing installed but Java. See [Pinned wrapper: nrgw](#pinned-wrapper-nrgw).<!--en-->
- **Везде одна и та же версия NRG.** Обёртка `nrgw` закрепляет в репозитории релиз и его sha256, как `mvnw` для Maven, и контрибьютор, задача CI и агент в свежей песочнице запускают одну версию, установив только Java. См. [«Обёртка nrgw с закреплённой версией»](#обёртка-nrgw-с-закреплённой-версией).<!--ru-->
